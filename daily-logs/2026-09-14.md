## Notes

- Pure BeeCluster is fast because it avoids LLM reasoning, but it cannot handle most natural-language MultiUAV-Plat tasks by itself
- Agent4Drone + BeeCluster reduced total latency and token usage on the selected tasks, but accuracy dropped compared with normal Agent4Drone
- The main issue was not BeeCluster's route scheduling itself; failures came from when the agent chose BeeCluster at the wrong time, selected the wrong target, or failed to recover from movement/coverage mistakes
- BeeCluster should be used as a low-latency planner for structured area coverage, while Agent4Drone should handle parsing, target discovery, obstacle avoidance, and recovery
